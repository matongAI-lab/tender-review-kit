# 招标文件审标对照清单（审标必查总清单）

> **kit 唯一的对照清单**——审标时**逐条对照**：有就抓进清单、没有就标"本招标无此条款"（不能默默漏）。
> 本清单合并了原「必拿废标点清单」+「特殊机制清单」，并沉淀 v1(bid-review-mcp) 实战经验。
> **规矩**：废标点 / 特殊坑 / 必拿字段都进这一份；新规则认家、不新建文件。
> 来源：跨多类标书实战（工程 / 货物 / 政采服务 / 央企）+ 反向校验暴露的漏点 + 真实案例沉淀。

---

## 〇、先做的锚点（最重要，决定 ▲ 算废标还是评分）

- **定位"实质性要求 / 否决条款"的明确范围**：招标文件明列的实质性要求有哪几项？（实战见过仅 2 项就锁定全文：最高限价 + 质保期）
  → 这是分清"▲ 是废标还是评分项"的**总闸**。落在范围内的 ▲ 才是废标，其余是评分项。
  → **找不到 = 危险信号**，在工作区标注"未定位到实质性要求范围，待人工"，不要默认全废标（虚增）或全评分（漏判）。

---

## 一、隐性门槛（最隐蔽，每份都要逐条对）

- **关系门槛**：加盖原厂/厂商公章、必须对接现有系统（钉钉/zoom 等）、必须接入现有平台、同一品牌限定、原厂授权链。**最容易漏的废标点，重点盯。**
- **原厂质保隐性成本**：质保年限（1/3/5/8 年/终身）、费用是否含在报价中（"费用包含在设备报价中"是高发隐性成本）、质保启动时间（验收/交付/出厂起）、质保性质（原厂/第三方/集成商）、范围（硬件维修/软件升级/现场服务）。
- **业绩绑定（⭐ 高频废标 + 评分双重点，6 要素全识别）**：
  - **类型**（如新建公共建筑智能化）/ **数量**（≥N 项）/ **单项金额阈值**（如 ≥450 万）/ **时间窗**（近 3 年 / 某起算日至投标截止）/ **身份**（以项目负责人身份参与）
  - **提交方式（别只认一种）**：业绩库平台可查（开标当天 / 公示期 / 中标前）、合同原件 / 复印件 / 扫描件、电子平台分栏目上传、纸质提交、多平台同时可查
  - **失效条件**：如"开标时业绩库未查到则该业绩无效"
  → 只识别"维度"，不绑某项目的具体值。

### 二补 · 评标程序必读规则（⭐ 反向校验高频漏点 — 不一定是废标，但漏了会判错/误判覆盖）

> 来源：厦门中远海运反向校验抓出主对话整理 disq 仍漏一批"评标程序条款"。这些常被当噪音跳过，但实际影响投标动作。

- **报价修正规则 + 优先级**（通常 4 个优先级：大写优先 / 单价优先 / 合价累计 / 缺漏项视为已含）——决定报价怎么被改，错了直接出局
- **异常低价启动情形**（政府采购常 5 个 / 工程类各异）——低于什么线触发澄清
- **推荐中标候选人规则**（平均分 / 得分相同 / 报价相同时怎么处置）
- **招标失败 / 重新招标情形**（有效投标 < 3 家、全部被否决等）
- **资格审查 + 符合性审查流程**（哪步刷人）

### 二补二 · 投标文件递交规格（⭐ 每份必对——形式 / 份数 / 封装，违反多为拒收/废标，高频漏点）

> 这三类要求几乎都在「投标人须知」的递交 / 密封章节，违反任一常直接拒收/废标，却最容易在赶清单时被跳过。逐项落实（无对应条款也要标"本招标无此条款"）：

- **递交形式**：纸质 / 电子（U盘·光盘）/ 网络平台投标（政采云、电子交易平台等）——**三者可能并存**（如"纸质正本 + 电子件 + 平台上传"）；网络投标还要看 CA 锁 / 电子签章 / 上传截止与解密时间。
- **份数**：正本 ___ 份 + 副本 ___ 份（+ 电子件 / U盘 ___ 份）；正副本不一致以谁为准；份数不符是否按废标处理。
- **封装 / 密封**：是否分册（资格 / 商务 / 技术 / 报价分开）密封；**报价（开标一览表）是否要求单独密封**；封套标记（项目名 · 包号 · 投标人 · "开标前不得启封"）；骑缝章 / 法人章 / 密封章要求；未按要求密封 = 拒收。

→ 违反项进**废标清单**（出处带须知行号）；纯要求项（份数 / 标记格式）进**提示**，供投标人备料时照做。

## 三、类型特化（对照本份标书属性，挑相关组各加 3-5 条；可多组并存）

> 不"先分类再套模板"——直接看这份标书命中哪几种属性（可同时命中），把相关条款补进清单。

**工程 · 经评审合理低价（招标投标法）**
- ▲ 标识参数任一不响应 = 实质性偏离 → 否决
- 注册建造师证书 / 业绩库平台开标当天可查 / 专业承包·总承包资质等级
- 关系门槛：现有厂商授权 / 加盖原厂公章
- 经评审合理低价法：**80 分地板、上下浮不对称** / 工程量清单偏差

**政府采购（服务 / 货物 / 工程，见"政府采购法 / 政采云 / 中小企业"）**
- 中小企业 20% 价格扣除（小微）+ 划型证明缺失即影响
- 信用中国失信查询（开标日 -1 周内截图）
- 演示视频 / U 盘现场递交（媒介 / 时长 / 份数）
- CCRC / ITSS / CMMI 资质（IT 服务）/ 节能产品政府采购清单 / 进口产品政策

**货物（招标投标法，见"采购 N 台 / 设备清单 / 技术参数表"）**
- ▲ 技术参数（常 60+ 项）实质性响应
- **CCC / 3C 三者一致**（申请人 / 制造商 / 生产企业）、不接受 OEM
- 入网证 / 备品备件 / 售后响应时间 / 验收标准
- 商务 + 技术 **2 偏离表**（替代单一标准表）

**央企 / 国企（见"集团 / 央企电子招标平台"）**
- **投标担保**（不是投标保证金）
- 集团合格供方目录 / 白名单
- 央企电子招标平台规则

## 四、4 个必扫产物 × 必拿字段（防"整类字段被漏"的自检表）

> 不同标书形式多样（章节 / 前附表 / N 表替代），但下面这些"维度"几乎永远有，照表逐字段自检。

| 必扫产物 | 必拿字段 |
|---|---|
| **投标人须知** | 项目编号·名称·采购人 / 限价·预算 / 投标截止·开标·平台 / 投标有效期 / 投标保证金（收否+金额）/ 履约保证金（收否+比例）/ 质保期 / 公告·答疑·质疑·异议期 / 演示视频要求 / 行业划型 / 联合体（接受否）/ 进口产品（限制否） |
| **评标办法** | 评标方法名 / 总分构成（价格+技术+商务）/ 价格分公式 / 异常低价启动情形 / 资格+符合性审查流程 / 报价修正规则（优先级）/ 推荐中标候选人规则 / 招标失败情形 / 中小企业价扣 |
| **评分细则（每项）** | 评审内容 / 评分梯度（逐档·含"分"字）/ 子项分值 / 必须材料 / 不提供的处置（不得分 / 不予认可） |
| **评审标准表（每行独立）** | 条款号 / 评审因素 / 评审标准 / 投标文件对应章节。**N 表替代**要合并（资格条件表 + 实质性要求表 + 客观分响应表 ≈ 否决条款详表）；跨表延续要接上 |

## 五、读取深度 · 领域常识（实战踩坑沉淀）

- **必有评分项（商务 + 技术）**：找不到评分专章/专表 → 报错或警告，不能默认"该项目没有评分项"
- **"详见下表 / 见前附表"必跟进**：别只看判决词命中段（曾因此漏 22 条评审表条款）
- **评审标准表每行 = 独立条款**，必须全部提取
- **评分细则提大类 + 逐档子项分值**，别只填大类摘要
- **商务 / 技术偏离表**（综合评估法常见）逐条提偏离扣分规则
- **加分项**：找"加分 / 另加 / 奖励分 / 优先分"
- **▲ 自适应识别**：不同标书可能用 ★ / ◆ / ● / ※ / ■ / *，按本份文档实际用的认
- **表格长行要拆**：Word 表格被摊平成一行时，同一行可能有多个 `▲/★/※` 参数。必须按标识符 + 编号/参数名逐条列，不得把一整行算一条。
- **图纸不直接跳过**：先试提取，文本极少才标"疑似图纸"
- **维度 vs 具体值**：识别"业绩证明 / 原厂质保期限"这个维度，不绑"双平台 / 5 年"具体值（详见 SKILL 铁律）

## 六、跨文件矛盾必比 5 项（招标包多文件时）

1. 子系统 / 工程范围数量（须知"等"字省略 vs 技术规范明文清单）
2. 时间节点（须知 vs 评标办法 vs 合同条款）
3. 限价金额（须知 vs 限价文件 vs 评标办法）
4. 资质要求（须知 vs 评审标准表）
5. 实质性要求（须知 vs 评审标准表 / 响应性评审）

> 前 3 项 `cross_doc.py` 能自动查；资质 / 实质性要求靠人读。**只列矛盾事实，不下哪个对，让人核。**

---

## 七、数量参考（只作"明显偏少"警示）

废标点一般十几条以上、评分项一般 8 项以上；某份**明显偏少**（如废标 < 8 条）→ 可能漏扫，回头查。
不按 A/B/C/D 设死基线——交给完整性护栏做"明显偏少"通用提醒 + 红蓝对抗兜判断死角。

## 使用方法

1. 先做 **〇 锚点**（定位实质性要求范围）。
2. **一、二** 逐条核——有对应条款则纳入清单，无则标"本招标无此条款"（也要写明，不能漏）。
3. **三** 按标书属性挑相关类型特化组（可多组并存）。
4. **四** 对照 4 必扫产物逐字段自检，防整类字段漏。
5. 每条都落到 **lines.txt 行号**（查漏程序 `check_coverage.py` 据行号反查覆盖）。
   → 出处**统一写成 `行103` 或 `行100-105`**（也认 `第103行`）；**裸数字 `103`、`第N页` 不算**——查漏只认带"行"字的写法（避免把金额/数量等数字误判成行号）。
